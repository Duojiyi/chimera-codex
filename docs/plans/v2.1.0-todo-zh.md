## 0. 执行规则

### 0.1 状态与优先级

- `[ ]` 未开始；`[-]` 进行中；`[x]` 已完成；`[!]` 阻塞。
- `P0`：阻断 v2.1.0 发布；`P1`：应随 v2.1.0 发布；`P2`：可在不破坏主目标时延后。
- 每项完成必须同时满足：代码完成、自动化测试完成、GitHub Actions 证据可追溯、验收标准通过。
- 禁止用“本机可以运行”代替 CI 证据，也禁止只验证配置文件存在而不验证 Codex Desktop 实际行为。

### 0.2 构建与测试边界

- 本机只允许：阅读/编辑代码、静态检索、`git diff`、`git diff --check`、`git status`、提交与推送。
- 本机禁止：`pnpm build`、`pnpm test`、`cargo test`、`cargo build`、`pnpm tauri build` 及任何安装包构建。
- 类型检查、单元测试、Rust 检查、故障注入、Windows/macOS 构建、签名、打包与发布全部由 GitHub Actions 完成。
- 候选包只能由手动触发的 candidate workflow 生成，不得直接创建正式 Release。

### 0.3 架构约束

- 后端是路由决策、供应商切换、认证状态、模型目录和 Codex 生命周期的唯一事实源。
- 普通用户只需填写供应商、API 地址/API Key 和模型映射；不得要求用户理解“本地路由”“takeover”或手动切换代理。
- 内部允许 `auto | direct | takeover`，默认且普通用户固定使用 `auto`；高级覆盖必须隐藏在高级设置中并带风险提示。
- 新前端不得继续复制后端路由判断规则；前端只提交用户意图、展示阶段状态和结构化错误。
- v2.1.0 的上游同步以 CC Switch v3.19.1 tag 为准；其后截至 2026-08-01 的远端 main 只有文档/赞助变更，不纳入功能基线。
