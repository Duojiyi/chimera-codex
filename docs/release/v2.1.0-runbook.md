# Chimera++ v2.1.0 发布与回退 Runbook

> 本 runbook 定义候选构建、正式发布和紧急停止 updater 的操作边界。候选工作流绝不创建 tag、GitHub Release 或 `latest.json`。

## 发布前门禁

1. `main` 的 **Windows Frontend Validation**、**Backend Validation (windows-2022)**、**Backend Validation (macos-15)** 全部成功。
2. `node scripts/verify-release-version.mjs --expect v2.1.0` 成功，确认 `package.json`、`Cargo.toml`、`tauri.conf.json` 和 `Cargo.lock` 均为 `2.1.0`。
3. 手动运行 **Candidate Build**，输入冻结 commit SHA 和 `2.1.0`；Windows 与 macOS artifact、`SHA256SUMS.txt`、依赖清单和 build provenance 均存在。
4. 对候选包执行官方/第三方认证、多模型目录、重启替换和 deeplink/MCP 风险提示的人工验收。
5. 必须在同步矩阵中记录未适配的上游安全项；若存在影响当前可达路径的 P0 项，禁止打 tag。

## 正式发布

1. 从已验收的 `main` commit 创建并推送已签名（如组织策略要求）`v2.1.0` tag。
2. `Release` workflow 负责跨平台打包、签名、上传 Release assets、生成 `latest.json`。
3. 该 workflow 必须先检查版本一致性，并在上传 `latest.json` 前验证版本、release URL、updater 签名字段、资产 SHA-256 与大小。
4. 发布负责人记录 Actions run URL、tag commit SHA 和候选 artifact 名称。

## 立即暂停 / 回退条件

出现以下任一情况，暂停 updater 并撤回/标为 pre-release 当前 Release：

- 任何 API Key、OAuth token 或敏感 URL query 出现在日志、诊断包或公开 artifact；
- 运行时误关闭 ChatGPT、其他 Electron 应用或非目标 Codex 安装；
- 官方/第三方切换出现认证循环、伪登录或不可恢复的 auth/config 状态；
- 模型目录大面积缺失、配置无法恢复，或更新后应用无法启动；
- 验证到 updater 的 `latest.json` 与真实 artifact、签名、版本或校验和不一致。

## 回退步骤

1. 禁止继续创建新 tag 或重新上传同名 asset；保存失败的 Actions log 和 correlation/诊断 ID，严禁上传未脱敏配置。
2. 将受影响 Release 设为非 Latest 或删除 `latest.json`，阻止客户端继续发现该更新。
3. 恢复已验证的上一稳定 Release（当前为 `v2.0.14`）的 `latest.json` 与资产，核对 SHA-256/签名。
4. 发布用户恢复公告：停止自动更新、手工安装上一稳定版本、保留 `~/.codex` 与 Chimera++ 配置备份、不手动伪造 auth.json。
5. 创建复盘 issue，补充回归 fixture 和 CI gate 后重新走候选流程。
